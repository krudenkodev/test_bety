# test_bety

## Запуск

Потрібен Flutter 3.41+ / Dart 3.11+.

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # генерує freezed/json_serializable файли
flutter run                                                 # запуск на емуляторі/девайсі
flutter test                                                # unit-тести алгоритму
flutter analyze                                             # лінт (має бути No issues found!)
```

`build_runner` потрібно перезапускати тільки після правок у файлах з анотаціями `@freezed` (`lib/models/domain/*.dart`).

## Структура

```
assets/booking.json                           ← вхідні дані (working hours, services, appointments)
lib/
  main.dart                                   ← bootstrap: setupServiceLocator() + MaterialApp
  di/service_locator.dart                     ← get_it: репозиторій, калькулятор, провайдер
  models/domain/                              ← Service, Appointment, WorkingHours, BreakInterval,
                                                BookingData, Slot, BookingRecord (freezed)
  services/
    booking_repository.dart                   ← AssetBookingRepository, читає JSON через rootBundle
    slot_calculator.dart                      ← вся бізнес-логіка обчислення слотів (чиста функція)
  provides/booking_provider.dart              ← ChangeNotifier: статус, обрана послуга/дата/слот, slots
  ui/slot_picker_page/
    slot_picker_page.dart                     ← SlotPickerPage (єдиний клас у файлі)
    widgets/                                  ← ServiceDropdown, DatePickerRow, SlotsGrid,
                                                SlotTile, ConfirmBar, ErrorView
test/
  slot_calculator_test.dart                   ← покриває всі edge cases з ТЗ
```

## Архітектурні рішення

### State management — Provider + ChangeNotifier
Розглядав три варіанти — Riverpod, Bloc і Provider з ChangeNotifier. Обрав Provider, тому що задача прямолінійна: є кілька джерел стану (послуга, дата, слот), які треба збирати в сітку, екран лише один і ділитись стейтом між фічами не треба. На такому обсязі Bloc і Riverpod дали б оверкод, а ChangeNotifier — стандартний шлях у Flutter без зайвої магії.

### SlotCalculator — чиста функція з ін'єктованим now
Усю бізнес-логіку обчислення слотів виніс в окремий клас, який нічого не знає ні про Flutter, ні про Provider, ні про системний годинник. Поточний час приходить параметром, тому в тестах я фіксую сьогодні на 2030-01-15 і не залежу від реальної дати запуску. Без цього не вийшло б нормально протестувати правило про слоти, що вже минули.

### Пріоритет причин disabled
Якщо слот недоступний одразу з кількох причин, користувачеві показую найважливішу. Спочатку перевіряю, чи час уже минув, потім чи слот виходить за межі робочого дня, далі чи перетинається з обідом, і наприкінці чи накладається на запис клієнта. Тобто слот, який і минув, і перетинає обід, отримає підпис «Час уже минув» — саме це майстру варто бачити в першу чергу.

### Буфер тільки навколо записів
П'ятнадцятихвилинний буфер застосовую тільки навколо існуючих записів — щоб майстру було коли прибрати робоче місце після клієнта і підготуватись до наступного. Початок робочого дня та обід — жорсткі межі без буфера: можна записатись рівно на 10:00 або закінчити процедуру рівно о 14:00, коли стартує обід.

### freezed + json_serializable для домену
Усі доменні моделі — Service, Appointment, BookingData — описані через freezed. Він автоматично генерує immutable-клас, рівність за значеннями, copyWith і парсер з JSON, тож рукописного коду менше і помилок теж. Для одного класу це справді надлишково, але вже на другій ітерації, коли треба додати поле в appointment, окупається. BookingRecord залишив звичайним Dart-класом, тому що там форматування дати й часу нестандартне і простіше написати власний toJson.

### get_it для DI
Репозиторій і калькулятор зареєстровані як lazy singleton — у них немає внутрішнього стану, який треба скидати. А BookingProvider реєструю як factory, щоб кожне нове відкриття екрана давало свіжий екземпляр. Це знімає дрібні проблеми із залишками попереднього стану після hot-reload або коли користувач закриває і знову відкриває екран.

### Один клас — один файл
Кожен віджет, який має власну поведінку — обробник тапу, похідний стан — лежить у своєму файлі в widgets. А зовсім тривіальні шматки: заголовки секції, повідомлення про порожній стан залишив на батьківских віджетах.

## Покриття тестами

Unit-тести `SlotCalculator` (14 кейсів):
- Сітка з кроком 15 хв, нижня межа робочого дня
- Слот, що закінчується рівно на `dayEnd` — валідний; за ним — `outOfWorkingDay`
- Слот, що закінчується рівно на початку обіду — валідний (без буфера)
- Слот, що стартує рівно на кінці обіду — валідний
- Буфер до й після існуючого запису
- Минулі слоти на сьогодні; пограничні випадки навколо `now`
- Усі 6 edge cases з ТЗ (150 хв на тісному дні → 0 слотів; 90 хв біля кінця дня; 10 хв до обіду; зміна 30→150 хв; два записи з мін. буфером)

## Що б доробив, якби було більше часу

- **Локалізація.** Зараз усі рядки зашиті українською в коді. У production — `intl` + `.arb`, з виділенням ключів типу `slot.disabled.past`, `slot.disabled.overlapsAppointment`.
- **Поведінка `now` як stream.** Якщо користувач залишив екран відкритим перед обідом, валідні слоти не закриваються в реальному часі. Можна підписатись на `Stream.periodic(const Duration(minutes: 1))` і перерахувати, або зробити мінімальний `Ticker` через `WidgetsBinding`.
- **Структуровані помилки.** `LoadingStatus.error` має retry-кнопку, але немає аналітики/логування. У prod версії — Sentry/Crashlytics + `Result<T, Failure>`.
- **Pull-to-refresh** на основному екрані — щоб оновити список записів без релоаду app.
- **Адаптивна ширина сітки.** Зараз 3 колонки незалежно від ширини екрана. Краще `LayoutBuilder` + breakpoint, на планшетах 4–6 колонок.
- **Анімації.** Перерахунок сітки відбувається миттєво. `AnimatedSwitcher` + `FadeTransition` зробили б UX м'якшим.
- **Винесення UI-стейту в окрему модель.** Зараз `BookingProvider` тримає і дані, і стан UI. Можна винести `_status`/`_error` в окремий `BookingUiState` (sealed class), а провайдер залишити лише для пробрасування події назовні.
- **`AutoSizeText` або `FittedBox`** для subtitle disabled-слотів. Зараз тайли мають фіксований `childAspectRatio: 1.35`, який підібраний під найдовший текст. Адаптивний скейл був би стійкішим до майбутніх правок текстів.
- **Кешування `BookingData`.** Зараз JSON парситься щоразу при відкритті екрана. Простий in-memory cache в репозиторії або `Hive`/`shared_preferences` пришвидшать повторне відкриття.
